# 桌面整理小工具 PRD、架构与开发路线

日期：2026-05-22

## 1. 产品定位

本工具是一个完全本地化、轻量级 Windows 桌面整理工具。它通过透明桌面面板和可拖动小组件，把桌面快捷方式、文件、文件夹以“分类格子”的形式重新组织展示。

核心原则：程序只维护自己的虚拟分类和窗口布局，不移动、不重排、不覆盖 Windows Explorer 真实桌面图标坐标。

目标用户：

- 桌面图标很多，需要按“软件、编程、AI 编程、建模、航测、文档”等分类管理的人。
- 希望像桌面小组件一样自由摆放分类区域的人。
- 不能接受程序崩溃、重启、关闭后把桌面图标布局弄乱的人。
- 需要低内存、低后台占用、可安装为 exe 的 Windows 用户。

## 2. 产品目标

### 2.1 必须实现

- 启动后扫描本机桌面项目，包括用户桌面和公共桌面。
- 支持把桌面项目放入不同分类格子中。
- 支持主画布模式：一个大面板内展示多个分类格子。
- 支持小组件模式：每个分类格子可独立拖动、缩放、折叠、锁定。
- 支持图标双击打开，行为接近原生桌面图标。
- 支持关闭程序后不影响真实桌面文件和图标坐标。
- 支持重启电脑后恢复用户主动保存的格子位置和尺寸。
- 支持分辨率、DPI、显示器变化时尽量保持布局稳定。
- 支持 exe 安装、卸载、开机自启选项。

### 2.2 强约束

- 不调用 Explorer 的桌面图标重排接口。
- 不主动修改 `IconStreams`、`Bags`、桌面 ListView 坐标等 Explorer 布局数据。
- 不把真实桌面文件移动到分类文件夹，除非未来用户显式启用“实体整理模式”。
- 不在后台高频轮询桌面状态。
- 不因为程序异常退出而覆盖最后一次正常布局。
- 不在系统恢复显示器配置时随意重写用户的窗口坐标。

### 2.3 暂不做

- 首版不做云同步。
- 首版不做 AI 自动分类。
- 首版不做跨电脑配置同步。
- 首版不替代 Windows Explorer。
- 首版不做实体文件夹整理。

## 3. 核心体验

### 3.1 主画布模式

主画布是一个透明或半透明桌面面板，用户可以把多个分类放在同一个面板里。

能力：

- 面板可拖动。
- 面板可缩放。
- 面板可折叠为标题栏。
- 面板可锁定，锁定后不能移动和缩放。
- 面板内可显示多个分类。
- 分类标签可位于上、下、左、右四个方向。
- 分类之间可切换，也可平铺显示。
- 支持搜索本分类或全部分类项目。

### 3.2 小组件模式

每个分类是独立桌面小组件，类似图三。

能力：

- 每个分类窗口独立保存位置、尺寸、折叠状态、透明度。
- 可任意拖动到桌面合适位置。
- 可单独锁定。
- 可单独折叠，只保留标题条。
- 可调整图标大小、行列间距。
- 可从主画布拆出为小组件，也可重新并回主画布。

### 3.3 图标交互

图标不是 Explorer 原生桌面图标，而是程序渲染的虚拟图标。

能力：

- 单击选中。
- 双击打开。
- 右键菜单：打开、打开文件位置、以管理员运行、重命名显示名、从分类移除、刷新图标。
- 拖入分类：从未分类区、其他分类、桌面文件拖入。
- 拖出分类：仅从当前分类移除，不删除、不移动真实文件。
- 支持快捷方式、文件夹、普通文件、URL 快捷方式。

## 4. 关键用户流程

### 4.1 初次启动

1. 程序读取用户桌面和公共桌面目录。
2. 生成“未分类”分类。
3. 把桌面项目以虚拟图标形式显示在未分类区域。
4. 用户新建分类，例如“软件”“编程”“文档”。
5. 用户把图标拖入不同分类。
6. 程序保存分类关系和面板布局。

### 4.2 日常启动

1. 程序加载上次正常保存的配置。
2. 扫描桌面项目变化。
3. 已存在项目按配置归类。
4. 新增项目进入“未分类”。
5. 已删除项目标记为丢失，可选择隐藏或清理。
6. 恢复格子位置、大小、折叠状态。

### 4.3 关闭程序

1. 保存程序自己的配置。
2. 关闭所有面板窗口。
3. 不修改 Explorer 桌面图标布局。
4. Windows 桌面保持原样。

### 4.4 系统重启或异常恢复

1. 程序启动时读取最后一次完整写入的配置。
2. 如果主配置损坏，读取备份配置。
3. 如果显示器配置变化，优先按显示器 ID 恢复。
4. 如果窗口完全落在屏幕外，仅临时拉回可见区域。
5. 不把临时修正立即写回配置，除非用户手动移动或保存布局。

## 5. 功能需求

### 5.1 分类管理

- 新建分类。
- 删除分类。
- 重命名分类。
- 调整分类顺序。
- 设置分类颜色或强调色。
- 设置分类图标。
- 分类折叠/展开。
- 分类锁定/解锁。
- 分类导出/导入。

删除分类时，分类内项目回到“未分类”，不删除真实文件。

### 5.2 布局管理

- 主画布布局。
- 独立小组件布局。
- 标签方向：上、下、左、右。
- 图标大小：小、中、大、自定义。
- 网格密度：紧凑、标准、宽松。
- 背景透明度。
- 标题栏透明度。
- 边框显示/隐藏。
- 锁定全部布局。
- 一键隐藏/显示全部格子。
- 保存当前布局为方案。
- 恢复默认布局。

### 5.3 桌面项目管理

- 扫描用户桌面目录：`FOLDERID_Desktop`。
- 扫描公共桌面目录：`FOLDERID_PublicDesktop`。
- 识别 `.lnk` 快捷方式。
- 识别 `.url` 快捷方式。

- 获取图标、显示名、目标路径、参数、工作目录。
- 支持打开文件位置。
- 支持刷新图标缓存。

### 5.4 搜索

首版搜索范围：

- 当前分类。
- 全部分类。
- 未分类项目。

搜索字段：

- 显示名。
- 文件名。
- 目标路径。

Everything 集成放到后续版本。

### 5.5 托盘与启动

- 托盘图标。
- 显示/隐藏全部格子。
- 锁定/解锁布局。
- 打开设置。
- 退出程序。
- 开机自启开关。

### 5.6 设置

- 开机自启。
- 启动时显示全部格子。
- 启动时保持上次隐藏状态。
- 双击打开方式。
- 单击/双击选择习惯。
- 图标缓存大小。
- 配置备份数量。
- 是否显示公共桌面项目。
- 主题：深色、浅色、跟随系统。

## 6. 非功能需求

### 6.1 性能

目标：

- 空闲后台内存：尽量控制在 20-50 MB 内。
- 空闲 CPU：接近 0%。
- 不做高频定时扫描。
- 图标缩略图异步加载。
- 配置变更防抖保存，避免频繁写盘。

### 6.2 稳定性

- 配置写入使用临时文件 + 原子替换。
- 每次正常保存前保留上一份备份。
- 启动时校验配置版本和完整性。
- 崩溃后不覆盖最后一次可用配置。
- 窗口恢复与显示器变化解耦。

### 6.3 隐私

- 完全本地运行。
- 不上传文件路径。
- 不上传快捷方式信息。
- 不依赖云服务。
- 不收集使用数据，除非未来用户明确开启本地日志导出。

### 6.4 兼容性

首版目标：

- Windows 10 22H2。
- Windows 11 23H2/24H2/后续主流版本。
- x64。

暂不承诺：

- Windows 7。
- ARM64。
- 远程桌面特殊环境。
- 第三方 Shell 替代 Explorer 的环境。

## 7. 推荐技术路线

### 7.1 首选技术栈

正式版本使用 C++ / Win32 / Direct2D。

理由：

- 后台内存最低。
- 对透明窗口、桌面层级、多显示器、DPI 控制更直接。
- 可做成原生 exe 和安装包。
- 不依赖浏览器运行时。
- 长期更适合桌面常驻工具。

主要技术：

- C++20。
- Win32 API。
- Direct2D / DirectWrite。
- Windows Imaging Component。
- Shell API。
- COM：`IShellLink`、`IPersistFile`、`IShellItemImageFactory`。
- JSON 配置：建议使用单头文件库 `nlohmann/json` 或等价轻量方案。
- 安装包：Inno Setup 或 WiX Toolset。首版建议 Inno Setup。

### 7.2 不推荐首版使用 Electron

Electron 界面开发快，但常驻内存明显偏高，不符合“几乎不占后台内存”的目标。

### 7.3 原型可选路线

如果需要快速验证 UI，可先用 C# WPF 做交互原型。但正式可安装版仍建议 C++ 原生实现。

### 8.2 模块职责

`AppCore`

- 负责程序启动、退出、单实例、托盘、全局设置。
- 处理全局事件，不直接操作 UI 细节。

`DesktopModel`

- 扫描真实桌面项目。
- 解析快捷方式目标。
- 维护项目唯一标识。
- 对外提供“桌面项目列表”，不负责窗口布局。

`Layout`

- 保存分类、窗口、格子、标签、图标大小等配置。
- 处理多显示器和 DPI 映射。
- 负责崩溃恢复和配置版本升级。

`UI`

- 创建主画布和小组件窗口。
- 处理拖拽、缩放、折叠、标签切换。
- 把用户操作转换成布局变更事件。

`Rendering`

- 使用 Direct2D 渲染半透明背景、边框、图标、文字。
- 管理图标缓存。
- 保证缩放和 DPI 下文字清晰。

`ShellIntegration`

- 打开项目。
- 打开文件位置。
- 以管理员运行。
- 监听桌面目录变化。
- 注册开机自启。

## 9. 桌面窗口层级设计

### 9.1 目标

窗口看起来像贴在桌面上，但不抢占普通应用窗口。

### 9.2 推荐策略

默认采用“桌面宿主内的无边框格子窗口”：

- 桌面宿主可用时使用 `WS_CHILD` 无边框窗口；不可用时才回退为 `WS_POPUP`。
- `WS_EX_TOOLWINDOW` 不显示在 Alt-Tab。
- 支持透明背景和点击命中测试。
- 不使用 TopMost 常驻压在所有应用上。
- 当用户显示桌面或桌面为前台时，格子可见。
- 当普通应用覆盖桌面时，格子自然被盖住或按设置隐藏。
- 优先作为 Explorer 桌面图标视图的子窗口加入桌面窗口树；持久化仍使用屏幕坐标，窗口创建和移动时转换为桌面宿主客户区坐标。

兼容回退：

- Explorer 桌面宿主暂不可用时，退回普通工具窗口并立即置于普通窗口 Z 序底部，避免覆盖已打开应用。
- 不注入 Explorer、不接管桌面 ListView 数据或图标布局；只利用窗口父子层级约束格子的可见层级。

### 9.3 桌面宿主的操作边界

格子仅把桌面图标 ListView 作为父窗口，不读取、写入或重排其中的图标项。直接操作 Explorer 桌面图标数据仍会带来高风险：

- 可能触发图标重排。
- Explorer 重启后状态不可控。
- Windows 版本差异明显。
- 第三方桌面工具容易冲突。

本产品必须把 Explorer 当成外部系统：窗口层级可依附桌面宿主，但业务数据只读取桌面目录，不接管 Explorer 布局。

## 11. 配置保存策略

配置目录：

```text
%APPDATA%\Luno\
├─ config.json
├─ config.backup.1.json
├─ config.backup.2.json
├─ icon-cache\
└─ logs\
```

保存流程：

1. 用户操作产生布局变更。
2. 进入防抖队列，例如 500-1000ms。
3. 写入 `config.tmp.json`。
4. 校验 JSON 可读。
5. 旧 `config.json` 复制为备份。
6. 使用原子替换更新 `config.json`。
7. 删除临时文件。

异常保护：

- 如果程序崩溃发生在临时文件阶段，不影响主配置。
- 如果主配置损坏，启动时读取最近可用备份。
- 如果显示器变化导致临时坐标修正，不立即写回配置。

## 12. 桌面变化监听

监听来源：

- 用户桌面目录。
- 公共桌面目录。

推荐实现：

- 使用 `ReadDirectoryChangesW`。
- 监听创建、删除、重命名、修改。
- 变化后延迟批量刷新，避免连续事件造成重复扫描。

不使用：

- 高频定时全量扫描。
- Explorer 图标坐标读取。

## 13. 图标渲染与缓存

图标获取：

- 快捷方式：解析目标后获取图标。
- 普通文件：Shell 图标。
- 文件夹：Shell 文件夹图标。
- 特殊快捷方式：保留 `.lnk` 自身图标。

缓存策略：

- 内存缓存当前可见图标。
- 磁盘缓存常用图标位图。
- 桌面项目变化时按路径和修改时间失效。
- 图标异步加载，先显示占位图。

### 14.1 程序内部拖拽

- 分类内调整顺序。
- 分类之间移动。

### 14.2 系统拖入

### 14.3 拖到系统外部

需要用户确认的动作：

- 删除真实文件。
- 移动真实文件。
- 修改开机自启。
- 清空分类。
- 重置全部布局。
- 导入配置覆盖当前配置。

首版默认不提供删除真实文件功能，只提供“从分类移除”。

## 20. 风险与规避

### 20.1 桌面层级兼容风险

风险：Windows 不同版本、不同 Explorer 状态下，桌面绑定窗口层级可能表现不一致。

规避：

- 默认绑定当前 Explorer 桌面图标宿主，并在创建时核验真实父窗口和窗口样式。
- Explorer 宿主不可用时使用底部普通窗口回退，绝不回退成覆盖应用的普通前置窗口。
- 用独立 Z-order 回归同时验证“桌面可见”和“普通应用覆盖”，避免只检查 `WS_EX_TOPMOST` 标志。

### 20.2 多显示器布局漂移

风险：显示器 ID、分辨率、DPI 改变导致窗口位置异常。

规避：

- 保存显示器 ID、坐标、DPI、工作区比例。
- 只做临时可见性修正。
- 用户确认或手动移动后才写回。

### 20.3 配置损坏

风险：断电、内存爆掉、强杀进程时配置写坏。

规避：

- 临时文件 + 校验 + 原子替换。
- 多份备份。
- 启动时配置恢复。

### 20.4 用户误以为删除分类会删除文件

风险：产品语义不清造成误解。

规避：

- 删除分类只回收项目到未分类。
- 真正删除文件首版不提供。
- 所有危险动作必须二次确认。

## 21. 成功标准

产品成功的最低标准：

- 用户可以每天开机自动使用。
- 桌面真实布局永远不被工具打乱。
- 用户手动摆好的格子位置不会因为重启、崩溃、分辨率变化被随意覆盖。
- 空闲时几乎没有存在感。
- 图标打开体验接近原生桌面。
- 配置损坏可以恢复。
